# Предложение: меньше idle-нагрузки PC Remote

Статус: план измерений; набор кнопок, время отклика и локальная модель безопасности не меняются.

Приложение состоит из API, web controller и tray companion. Основной риск лишнего потребления — частая проверка системного состояния или повторное получение тех же данных при открытом контроллере.

## Срез

- [ ] Замерить idle CPU/RAM при запущенном приложении без открытого телефона, с активной вкладкой, с фоновой вкладкой и при нажатии контролов.
- [ ] Снять частоту обращений UI к API; отделить необходимые живые показатели от редко меняющихся сведений о приложениях/окнах.
- [ ] Замерить p95 от нажатия до завершения volume/media/window action.

## Кандидаты

- [ ] Кэшировать read-only справочные данные только на срок, допустимый их фактической изменчивостью; обновлять по явному действию и при завершении операции, меняющей это состояние.
- [ ] Проверить, не повторяют ли tray и API одинаковые дорогие OS queries; где возможно, передавать свежий уже полученный снимок.
- [ ] Для фоновой/скрытой вкладки снизить частоту только некритичных status refresh; активный экран и действия пользователя сохраняют текущую скорость.
- [ ] Освобождать временные ответы и списки приложений после отправки; установить ограничение размера только у кэша, не у доступных пользователю элементов.
- [ ] Не добавлять WebSocket, AI, сервис, БД или новый framework ради оптимизации.

## Приёмка и ограничения

Все endpoints, команды, auth/rate limiting и UI остаются теми же. Проверить volume/media/window/power flows и актуальность состояния после изменений. Сравнить idle CPU/working set и p95 control latency; принимать только уменьшение idle-нагрузки без ухудшения latency активного действия и без устаревшего состояния.
